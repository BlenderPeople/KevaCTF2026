## Информация

> Заброшенный терминал всё ещё принимает подключения. Голос по имени Alice
> подсказывает, что искать нужно не там, где светло.
>
> http://<ip>:57778

## Деплой

```sh
cd deploy
docker-compose up --build -d
```

## Выдать участникам

IP:PORT сервера

## Описание

Терминал-стилизованное веб-приложение «Лабиринт»: профиль, отправка токенов
другим пользователям и библиотека файлов. Часть файлов открывается только по
правильному токену — задача найти способ его получить.

## Решение

1. В ходе анализа web-приложения замечаем ручку `/send-token` — при отправке
   токена другому пользователю сервер делает POST-запрос на указанный `url`,
   отправляя `user_id` целевого пользователя из БД и `token` — значение, которое
   мы сами указали в форме. Также видим, что на `/files` есть `TopSecretFile`,
   который требует access token администратора из базы данных.

2. Меняем `url` в запросе на свой (webhook.site) и отправляем форму с
   `login=admin`. Перехватываем запрос — в теле получаем `user_id: 354969`
   (это id администратора из БД) и наш отправленный `token`. SSRF нужен
   именно для получения `user_id` администратора.

3. Подделка JWT: нам нужно создать JWT с `sub=354969` и `username=admin`, но
   для этого нужен секретный ключ подписи. Берём свой JWT из cookie
   `access_token` и брутим секрет через hashcat:
   `hashcat -a 0 -m 16500 <jwt-token> rockyou.txt`.
   Получаем секрет — `trustno1` — и переподписываем токен с payload админа.

4. Устанавливаем forged JWT в cookie `access_token`. Заходим на `/profile` —
   сервер видит `sub=354969`, находит access token администратора в БД и
   отображает его на странице. Копируем этот токен.

5. Открываем `TopSecretFile`, вставляем access token администратора из профиля —
   получаем флаг.
