# Uplink

## Описание

Участнику предоставляется TCP-сервис на asyncio (порт `64444`). При подключении сервис генерирует случайное задание и присылает его текстом, а затем ждёт от клиента один ответ — целое число, посчитанное по присланным данным.

## Формат сообщения сервера

```
Селекторные байты (HEX):
<HEX-байты через пробел>

Последовательность:
<РЕЖИМ>
<HEX-байты TLV-потока>

<РЕЖИМ>
<HEX-байты TLV-потока>

...
Передай итоговый контрольный индекс одним целым числом:
```

- **Селекторные байты** — список байт (в HEX), используемых режимом `SEL`.
- Далее идёт от 14 до 30 раундов. У каждого раунда есть **режим** (`SUM`, `MAX` или `SEL`) и строка байт потока в HEX.

## Формат TLV-потока

Поток раунда — это последовательность записей вида:

| Поле   | Размер     | Описание                    |
|--------|------------|------------------------------|
| Type   | 1 байт     | Тип записи (0–255)          |
| Length | 1 байт     | Длина данных (1–24)         |
| Value  | Length байт | Сами данные                 |

Записи идут подряд без разделителей, пока не кончится поток.

## Правила подсчёта

Для каждой TLV-записи в раунде, в зависимости от режима раунда:

- **`SUM`** — к общей сумме прибавляются все байты Value этой записи.
- **`MAX`** — если длина Value этой записи больше текущего максимума, максимум обновляется.
- **`SEL`** — если Type записи есть среди селекторных байт, счётчик увеличивается на 1.

Важно: суммы, максимум и счётчик **не сбрасываются** между раундами одного режима — они накапливаются по всем раундам за всё соединение.

Итоговый ответ — сумма всех трёх величин: `SUM + MAX + SEL`.

## Ограничение по времени

На отправку ответа даётся 6 секунд с момента получения задания — вручную посчитать не успеть, нужен скрипт.
