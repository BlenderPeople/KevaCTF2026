# Uplink | Hard | ppc

## Информация

> На заброшенной станции слежения ожил старый приёмник: он поймал служебный канал телеметрии, который выходит на связь короткими сессиями и почти сразу отключается. Ваша задача — написать скрипт, который успеет принять сессию, разобрать поток и отправить назад один-единственный контрольный индекс, пока приёмник не потерял сигнал.
>
> nc <ip> 64444
>
> **Формат сессии.** Приёмник сначала присылает строку «Селекторные байты (HEX)» и список байт через пробел — они понадобятся позже. Затем идёт раздел «Последовательность»: несколько раундов, каждый начинается со строки-режима (`SUM`, `MAX` или `SEL`), за которой следует одна строка данных раунда в HEX.
>
> **Формат данных раунда.** Это склеенные подряд TLV-записи (Type-Length-Value), без разделителей между ними: 1 байт — тип записи (0–255), 1 байт — длина данных (1–24), затем сами данные этой длины. Так продолжается, пока не кончится строка.
>
> **Что нужно посчитать.** Для каждой TLV-записи, в зависимости от режима её раунда:
> - `SUM` — прибавить к общей сумме все байты данных записи;
> - `MAX` — обновить максимум, если длина данных записи больше текущего;
> - `SEL` — если тип записи есть среди селекторных байт из начала сообщения, увеличить счётчик на 1.
>
> Важно: эти три значения общие для всей сессии — они не сбрасываются между раундами одного режима, а накапливаются по всем раундам целиком. Финальный ответ — это сумма всех трёх накопленных значений одним целым числом.
>
> На отправку ответа даётся всего 6 секунд с момента получения сообщения.

## Описание

Участнику предоставляется TCP-сервис, который присылает поток данных в формате TLV и список «селекторных» байт. Нужно написать скрипт, который разберёт поток и посчитает контрольный индекс по описанным в задаче правилам, уложившись в таймаут.

## Решение

1. Сервис присылает список селекторных байт, затем несколько раундов данных: у каждого раунда есть режим (`SUM`, `MAX` или `SEL`) и строка байт в HEX в формате TLV — каждая запись это `тип (1 байт) | длина (1 байт) | данные (length байт)`.
2. Для каждого раунда нужно разобрать все TLV-записи и, в зависимости от режима раунда, накопить:
   - `SUM` — сумму всех байт данных;
   - `MAX` — максимальную длину данных среди записей;
   - `SEL` — количество записей, чей тип встречается в списке селекторных байт.
3. Все три величины накапливаются по всем раундам своего режима (не сбрасываются между раундами), и ответ — их сумма.
4. Отправить посчитанное число в ответ до истечения таймаута.
