# Incident

## Описание

Участнику выдаётся файл `error.png` — PNG-полиглот, содержащий несколько слоёв скрытых данных, которые нужно вскрывать последовательно.

## Слой 1: полиглот PNG + ZIP

`error.png` состоит из двух конкатенированных частей:

1. Полноценный валидный PNG (`incident.png`) — то, что видно при обычном открытии файла.
2. ZIP-архив, приклеенный сразу после конца PNG (после чанка `IEND`).

PNG-декодеры останавливаются на `IEND` и не читают ничего после него, поэтому файл спокойно открывается как обычная картинка. Но ZIP-инструменты ищут центральную директорию с конца файла, поэтому `unzip error.png` или `binwalk -e error.png` успешно извлекают архив, игнорируя PNG-данные в начале.

## Слой 2: извлечённый архив

Внутри архива лежит `SYSTEM_BREACH_DETECTED.png` — контейнерная картинка 640×120 с красным текстом на чёрном фоне.

## Слой 3: подсказка в метаданных

В `SYSTEM_BREACH_DETECTED.png` внедрён кастомный `tEXt`-чанк (`Comment: use zsteg`), который виден через `strings`, `exiftool` или любой PNG-chunk-инспектор. Он указывает на инструмент для следующего шага.

## Слой 4: LSB-стеганография

Флаг побитово записан в младший бит (LSB) каждого байта R, G, B всех пикселей `SYSTEM_BREACH_DETECTED.png` — по одному биту на канал, пиксели по порядку слева направо, сверху вниз, по 8 бит на символ ASCII. Извлекается через `zsteg` или вручную (см. [solve.py](solve.py)).

## Валидация

Каждый слой можно проверить независимо: файл одновременно валиден и как PNG, и как ZIP; извлечённый PNG — корректный файл со стандартным `tEXt`-чанком; сам флаг читается обычным LSB-экстрактором без дополнительных преобразований (без инверсии битов и перестановок).
